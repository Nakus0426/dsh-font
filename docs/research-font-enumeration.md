## 1. The Remote (host↔client RPC) mechanism

### 1.1 The four participants

| Layer | Package | Role |
|---|---|---|
| Protocol / decorators | `@deepseek-ai/dsh-typert-protocol` | `@Remote`, `@RemoteScope`, `RemoteError`, `TypertRemoteService`, `TYPERT` descriptor shape, `TypertClientRemote` (only `$mount()` / `$on()`). Registers **no** Cordis service. |
| Generator output | `lib/typert.host.js`, `lib/typert.remote-client.js` | **Generated**, one pair per owner package, emitted by `@deepseek-ai/dsh-typert-generator` from a "FaceModel". Header literal: `/* Generated by @deepseek-ai/dsh-typert-generator from FaceModel — do not edit. */` |
| Runtime registry | `@deepseek-ai/dsh-typert-registry`, `dsh-typert-loader` | Stores descriptors/providers at runtime; `dsh-typert-loader` has only `lib/index.js` (host-side loader). |
| Host gateway | `@deepseek-ai/dsh-api-gateway` (`lib/index.js`) | Owns endpoints, carriers, cancellation, reconnection. |
| Client gateway | `@deepseek-ai/dsh-api-gateway/lib/types/client/index.js` | Creates `ctx.remote.<ns>` **Cordis Services** in the *client* root. |
| Application BFF | `@deepseek-ai/dsh-api-remotes` | Host entry registers the forwarded-event source; client entry `$mount()`s each selected contribution. |

### 1.2 How the plugin author declares the contract

From `@deepseek-ai/dsh-typert-protocol/README.md:32-49`:

> A business package marks a public instance method with `@Remote` (or `@RemoteScope(key)` …), and the owning service either extends `TypertRemoteService` or declares a `typertRemote` binding through `bindTypertRemote()`:
> ```ts
> import { Remote, TypertRemoteService } from '@deepseek-ai/dsh-typert-protocol'
> export class GoalService extends TypertRemoteService {
>   @Remote
>   async create(agentId: string, objective: string): Promise<GoalResult> { … }
> }
> ```
> Generation turns the method into a wire endpoint under the service's namespace; Clients call it as a typed method through `ctx.remote` … A method opts into cooperative cancellation by declaring `signal: AbortSignal` as its final parameter — the signal is injected, never a JSON parameter.

**There is no hand-written contract file.** The author writes plain TypeScript with decorators; the
build pipeline (`dsh-typert-generator`) reads the TypeScript types and emits **both** faces:

- `lib/typert.host.js` — zod schemas + the `TYPERT` descriptor consumed by the Host Gateway.
- `lib/typert.remote-client.js` — the same descriptors, consumed by the Client `$mount()`.
- plus `lib/typert.host.d.ts` / `lib/typert.remote-client.d.ts` for the type face.

And exposes them as subpath exports. Proof — `@deepseek-ai/dsh-api-settings-controller/package.json`:

```json
"exports": {
  ".":        { "types": "./lib/types/index.d.ts",           "default": "./lib/index.js" },
  "./types":  { "types": "./lib/types/types.d.ts",           "default": "./lib/types/types.js" },
  "./typert": { "types": "./lib/typert.host.d.ts",           "default": "./lib/typert.host.js" },
  "./remote": { "types": "./lib/typert.remote-client.d.ts",  "default": "./lib/typert.remote-client.js" }
}
```

**Answer to "typert/typert-registry step?":** yes — there is a real generated-types step, but the
generated artifact is **not** a shared `dsh-remote-*` contract package. Each *owner* package emits
its own `/typert` + `/remote` subpaths, and the **client** consumes them through the
`@deepseek-ai/dsh-api-remotes` assembly, which imports them as **runtime values** and mounts them.

`$mount` is the only entry point. `dsh-api-remotes/lib/client.js:12989-13032`:


`mountContribution` groups descriptors by namespace (:107-121) and `createNamespace` (:214-239) spins a
Cordis **plugin fiber named `remote.<namespace>`** and constructs the namespace Service:

```js
const fiber = this.ownerCtx.plugin({
    name: remoteServiceKey(name),                                                       // :218
    apply: (ctx) => {
        service = new RemoteNamespaceService(ctx, name, (direct, scoped, caller, args) =>
            this.invokeMethod(direct, scoped, caller, args));                            // :220

```

with (`:446-450`, `:554-556`):

```js

function remoteServiceKey(namespace) { return `remote.${namespace}`; }                   // :554-555
```

and methods installed as lazily-bodied getters that forward through the carrier (`:475-487`):

```js
Object.defineProperty(this, method, {
  configurable: true, enumerable: true,
  get: function () {
    const callerCtx = this.ctx;
    const current = this.methods.get(method);
    const direct = current?.direct, scoped = current?.scoped;
    return (...args) => this.invokeRemote(direct, scoped, callerCtx, args);
  },
});
```

**So on the client, the typed proxy is a real Cordis Service named `remote.<namespace>`, and a
client plugin declares it in `inject`.**

### 1.6 Request/response vs streams

Both. From `dsh-typert-protocol/README.md:49`:

> A stream method (`@Remote({ mode: 'stream' })`) returns `Iterable`, `AsyncIterable`, or
> `RemoteStream<Out, In>`. … A generated Client stream method returns `RemoteStreamHandle<Out, In>`:
> the handle with `send`, `end`, and `dispose` beside the downlink iteration.

Descriptor discriminator is `invocation.kind`: `'direct'` or scoped. Client-side the gateway tracks
`direct` and `scoped` token sets per method (`index.js:153-158`) and exposes
`this.streams` (`RemoteStreamMuxClient`) over the `/api/remote.mux` WebSocket for streams.

### 1.7 Wire constraints that matter for a font list

From `dsh-typert-protocol/README.md:47`:

> A unary method can return `Uint8Array` directly or within nested objects, arrays, tuples, optional
> fields, unions, and recursive types. … Pure JSON results pass through without Host byte detection or
> Client parsing. **Parameters, events, and stream items remain JSON-only**; runtime object cycles are unsupported.

A `string[]` result is trivially supported. `RemoteError` codes must satisfy
`isTypertRemoteSegment()`, and business codes are declared by merging `RemoteErrorDetailsMap`
(`README.md:59-68`).

### 1.8 The build-boundary constraint (the real cost)

`dsh-api-remotes/README.md:52`:

> Most repository packages belong to one TypeScript face: Host packages are registered in the root
> `tsconfig.host.json`, and Client packages in `tsconfig.client.json`. This package splits because its
> Host entry must participate in the Host Typert graph, while `src/client/index.ts` **cannot compile
> until Host tsdown has generated** the business packages' `/remote` declarations.

and `README.md:73-75` (Known Limitations):

> - The capability set is fixed by **explicit build-time value imports**; the Client does not discover
>   the Host's active Services or Remote definitions at runtime.
> - Additional capabilities require an **explicit `/remote` value import and mount in this assembly.**

**Consequence for the font plugin — this is the architectural blocker:** a *third-party* plugin
cannot add a new Remote namespace by itself, because `dsh-api-remotes/lib/client.js` contains a
hard-coded array of 23 `TYPERT_REMOTE*` values (line 13000-13023). Shipping a new namespace requires
patching that array. Changing the shipped bundle without a build of `dsh-api-remotes` is not possible
from a plugin package. Options:

1. **Reuse an existing already-mounted namespace.** The cleanest is `settings` (namespace
   `settings`, service `settingsController`) — but its methods are a closed set
   (`describe`/`update`/`replace`/`mutate`/`openSettingsDocument`), and `mutate`/`update` take
   `Record<string, JsonValue>` patches. **A font list is not retrievable through them.**
2. **Use an HTTP route** (see §2c) — fully plugin-local, no core patch.
3. **Use an SSE route** (see §2e) — fully plugin-local, no core patch.

(Note the inventory/read-only namespaces that *are* already mounted and might be abused as a
generic value channel: `pluginInventory` with `list()`, and `dynamicCordisRunner`. `pluginInventory`
returns a fixed inventory shape — `dsh-client-ui-plugin-manager/lib/client.js:781` —
`const inventory = await this.ctx.remote.pluginInventory.list();` — so it is not generic.)

So: **route paths must live under `/api/`**, must declare ≥1 method, must be unique, and
`requestBody` must be declared (`"buffered"` or streaming) before the bridge reads bytes

returns **401 before dispatch**; a bad Host/Origin returns 403. I verified this live on the running GUI:

```
=== probe GUI origin ===
ERR: 响应状态代码未指示成功: 401 (Unauthorized).
```

That 401 is the fence — a plain unauthenticated `Invoke-WebRequest` to `http://127.0.0.1:19387/`
is rejected exactly as documented. The browser's same-origin `fetch()` carries the signed cookie
automatically, so a **client plugin needs no auth code**.

**Is a JSON file even needed?** No. The handler can enumerate fonts in-process and return
`Response.json(catalog)`. Writing a file is strictly worse: it adds staleness and a second failure
mode. If you *do* want caching, `libreoffice-kit` already demonstrates the right shape
(`font-metadata.json` keyed by `dev/ino/size/mtimeMs/ctimeMs` + sha256 digest +
`format`/`extractor`/`fontkit` version fields — `font-snapshot-worker.js:273-381`).

### (a) New Remote namespace returning a list — mechanically correct, but blocked by the assembly

There is **no way for a plugin to declare a new namespace without patching
`dsh-api-remotes/lib/client.js`**, for the reasons in §1.8. If you *are* willing to fork, the shape
is fully specified by the settings-controller example, and a `list()` method returning `string[]`
would generate (`lib/typert.host.js` style):

```js
{
  id: '@your/dsh-host-font-catalog#fonts/list',
  service: 'fontCatalogController',
  namespace: 'fonts',
  method: 'list',
  invocation: { kind: 'direct' },
  parameters: [],
  result: { mode: 'strict',
            typeSymbol: '@your/dsh-host-font-catalog#fonts/list:result',
            create: () => z.array(z.string()) }
}
```

Client side would then be `inject: ["remote.fonts"]` and `await ctx.remote.fonts.list()`.
**Only choose this if you are forking the shipped app.**

### (b) Cordis host Service injected into the client — **impossible**

Three independent proofs:

1. **Different Cordis roots.** The host half runs in the Electron/Node process in `lib/index.js`;
   the client half is a browser bundle wrapped in `window.__ModuleLoader__.load({...})`
   (`dsh-client-hmr/lib/client.js:1`, `dsh-api-remotes/lib/client.js:1`). Cordis `inject` resolves
   against the *local* root's service container.
2. **The client-side name is derived, not the host name.** `createNamespace` registers the Service as
   `remote.${namespace}` — `dsh-api-gateway/lib/types/client/index.js:447,554-555`. A host
   `ctx.fontCatalog` service never appears client-side under that name.
3. **The seam has no client half.** `dsh-host-directory-picker`'s entire file list is
   `LICENSE, package.json, README*, lib/index.js, lib/types/index.js, lib/types/types.js` — there is
   no `./client` export and no `dsh.client` field in its `package.json`. Its capability only reaches
   the client **after** `dsh-api-workspace-controller` wraps it as a Remote namespace.

The only client-visible services from the host are those `$mount`ed into `ctx.remote.<ns>`.

### 3.3 Recommendation: do **not** use `queryLocalFonts`

Reasons, all evidenced:

1. **It needs a user-activation permission prompt per origin.** The app's own trust model (`dsh-client-connection/README.md:36-45`) is explicitly *"Every Host RPC method and WebSocket stream requires one browser session; there is no method-specific loopback tier"* — a second, browser-native consent gate is foreign to it.
2. **It returns the *localized* family name** — the same class of value the registry gives you, and §5 shows how unreliable that is for CSS. Chromium's `FontData.family` is the DirectWrite family name, which for CJK is locale-dependent.
3. **Nothing in the codebase does it**, so it is unproven in this shell; and the Electron main process is **not in the extraction** (`D:\dsh-asar-ref\dsh` contains only `node_modules/`, `package.json`, `desktop-runtime.json`; the Electron entry lives inside the packed 117 MB `app.asar`), so I cannot verify that no `setPermissionRequestHandler` denies it. That is an unverifiable risk.
4. **The host can already enumerate fonts better** (§4/§5) and hand them over via §2c.

**Verdict: enumerate on the host, deliver via a `/api/...` GET route.**

```js
import { execFileSync } from 'node:child_process';

const KEYS = [
  'HKLM\\SOFTWARE\\Microsoft\\Windows NT\\CurrentVersion\\Fonts',
  'HKCU\\SOFTWARE\\Microsoft\\Windows NT\\CurrentVersion\\Fonts',
];
const SUFFIX = /\s*\((?:TrueType|OpenType|All res|\d+)\)\s*$/i;

export function readFontRegistry() {
  const rows = [];
  for (const key of KEYS) {
    let text;
    try {
      // /reg:64 avoids the WOW6432Node view on 32-bit hosts.
      text = execFileSync('reg.exe', ['query', key, '/reg:64'], { maxBuffer: 32 * 1024 * 1024 })
        .toString('utf8');
    } catch { continue; }              // key absent → skip, never throw
    for (const line of text.split(/\r?\n/)) {
      const marker = '    REG_SZ    ';
      const at = line.indexOf(marker);
      if (at < 0) continue;
      const display = line.slice(0, at).trim();
      const value = line.slice(at + marker.length).trim();
      if (!display || !value) continue;
      rows.push({
        display,
        family: display.replace(SUFFIX, ''),
        file: value,                    // often a bare basename like "arial.ttf"
        perUser: key.startsWith('HKCU'),
      });
    }
  }
  return rows;
}
```

> PowerShell and parse `ConvertTo-Json` output (what I actually used to produce `registry.json`), or
> to set the codepage first. Do not hand-roll UTF-16LE — `reg.exe` does **not** emit UTF-16 when piped.

```js
// libreoffice-kit/lib/font-snapshot-worker.js:114-147  (verbatim, comments added)
let faces;
try {
  const parsed = create(bytes);                                   // :115  buffer, not path
  faces = ("fonts" in parsed ? parsed.fonts : [parsed])            // :116  ← THE .ttc FALLBACK
    .map((font, faceIndex) => {
      const names = [
        "fontFamily",          // name ID 1  — canonical CSS family
        "preferredFamily",     // name ID 16 — typographic family (what modern CSS wants)
        "fullName",            // name ID 4
        "postscriptName"       // name ID 6
      ].flatMap((key) => Object.values(font.name?.records[key] ?? {}))  // :122  ← ALL locales
       .filter((name) => typeof name === "string");
      const aliases = [...new Set([
        ...names,
        font.familyName,       // :125  fontkit's resolved convenience accessor
        font.fullName,
        font.postscriptName

      return {
```

**Minimal version for the picker** (path-based, which is fine for a one-shot enumeration — `openSync`
is ~3.6 ms/file, see §5.4):

```js
import { openSync } from 'fontkit';

/** @returns {{family:string, style:string, cssFamily:string, weight:number, italic:boolean, fixed:boolean}[]} */
export function readFaces(filePath) {
  const parsed = openSync(filePath);
  const list = parsed.fonts ?? [parsed];          // .ttc/.otc → collection; else one face
  return list.map((font) => {
    const os2 = font['OS/2'];
    // Prefer the typographic family (name ID 16) when present, else name ID 1.
    const preferred = font.name?.records?.preferredFamily;
    const preferredEn = preferred?.en ?? (preferred ? Object.values(preferred)[0] : undefined);
    return {
      family: font.familyName,                    // css-usable, always English
      preferredFamily: preferredEn,               // may be undefined
      style: font.subfamilyName,                  // "Regular" | "Bold" | "Italic" | …
      cssFamily: preferredEn ?? font.familyName,  // ← THE VALUE TO PUT IN CSS
      weight: os2?.usWeightClass ?? 400,
      width: os2?.usWidthClass ?? 5,
      italic: font.italicAngle !== 0,
      fixed: Boolean(font.post?.isFixedPitch),
      postscriptName: font.postscriptName,
    };
  });
}
```

**Fallbacks for `.ttc` collections** — this is the sharp edge:

1. `parsed.fonts` is the collection face array; `parsed` itself is **not** a usable face. Using
   `font.familyName` on a collection object yields the *first* face only — you would silently drop
   `Microsoft YaHei UI` and `Cambria Math`. **Always branch on `parsed.fonts`.**
2. However, `fontkit` also sets `parsed.numFonts`. `msyh.ttc` → `numFonts: 2`; `cambria.ttc` → `2`.
3. `familyName` **can be identical across faces with different subfamilies** within one collection —
   collapse by `cssFamily` (see §5.3).
4. `create(buffer)` (what DSH uses) and `openSync(path)` behave the same for `fonts`; DSH reads bytes
   itself (`openSync`/`fstatSync`/`readSync` with `O_NOFOLLOW|O_NONBLOCK`, `font-snapshot-worker.js:89-112`)
   for TOCTOU safety and to avoid holding path handles. That is worth copying for the cache-keyed
   path, but is over-engineering for a picker.

**Weight/style must be folded into the CSS family, not into the name.** `font.subfamilyName` maps to
`font-weight`/`font-style`: `Regular`→400 normal, `Bold`→700, `Italic`→400 italic,
`Bold Italic`→700 italic, and `OS/2.usWeightClass` is the exact numeric value. Never build
`"Arial Bold"` as a family.

### 5.4 Performance (measured, real numbers)

```
font files found: 394
elapsed ms: 1412  failed files: 0
```

**~3.6 ms per file** with `fontkit.openSync`, 1.4 s for the full machine, **0 failures**. For an
HTTP handler that is too slow to run per request on every picker open, but fine to run once and
cache. Two mitigations, both already modelled by DSH:

- **Cache keyed on file identity.** `font-snapshot-worker.js:285-292` keys on
  `["size","mtimeMs","ctimeMs","dev","ino"]` and only re-parses when one changes
  (`:169-180`); it persists `font-metadata.json` with a sha256 `digest` over the records and
  `{format, extractor, fontkit}` version stamps (`:275-279`, `:337-345`).
- **Worker thread.** DSH runs the whole scan in a `node:worker_threads` Worker
  (`font-snapshot-worker.js:1`, `:436-453`) so a UI request never blocks the host event loop. For a
  picker you may instead cache in memory at plugin `apply()` and refresh on demand.

Also note `maxFontFiles: 2e4` / `maxFontFileBytes: 256 MiB` guards — copy them; a `.ttc` can be large
and a runaway directory can hang the host.

```
   postscriptName [2 lang] en="DengXian"  zh="Dengxian"
```

Caveats, in order of importance:

1. **`font.familyName` returns the `en` record.** `simsun.ttc` → `SimSun`, not `宋体`. `msyh.ttc` →
   `Microsoft YaHei`, not `微软雅黑`. **This is the safe choice.** On Windows, DirectWrite resolves
   CSS family names by matching the name table, and Chromium's `FontCache` adds the localized names as
   aliases in the app locale — but the English name works in *every* locale. **Put the English name in
   CSS.**
2. **Offer the localized name as a display/search alias, never as the CSS value.** DSH's own scanner
   does exactly this — `Object.values(font.name?.records[key] ?? {})` (`:122`) harvests *every*
   locale into `aliases`, which are then used for *matching* (`officeFontFace`, `:227-229`) not for
   output. Copy that split.
3. **`simsun.ttc` has `zh` AND `zh-SG` records** (Simplified Chinese + Singapore), both `宋体`.
   Deduplicate after NFKC normalization.
4. **`msyh.ttc` face 1's `postscriptName` differs by locale** (`MicrosoftYaHeiUI` vs
   `MicrosoftYaHeiUIRegular`). Never key a font by localized PostScript name; use the `en` one.
5. **`subfamilyName` is localized but you do not need it for CSS** — map to
   `font-weight`/`font-style` numerically via `OS/2.usWeightClass` (`:84`) instead. Note `zh="常规"`
   vs `en="Regular"` for `simsun.ttc`, and that `msyh.ttc` has **25** `fontSubfamily` locale records
   but only **2** `fontFamily` records — the family name table is stable, the style table is not.
6. **A single `.ttc` can hold semantically unrelated families.** `cambria.ttc` → `Cambria` **and**
   `Cambria Math`; `msyh.ttc` → `Microsoft YaHei` **and** `Microsoft YaHei UI`; `simsun.ttc` →
   `SimSun` **and** `NSimSun`. The registry collapses these into one row (`"Cambria & Cambria Math"`).
   Iterating `parsed.fonts` is mandatory, and `faceIndex` must be part of any cache key.
7. **CJK families are typically single-weight in one file but multi-file in aggregate.** `Noto Sans
   SC` on this machine resolves from `notosanssc-vf.ttf` (a variable font — one file, many weights)
   while `Source Han Serif SC Heavy` is a separate per-weight file. Variable fonts report a single
   `familyName` from `openSync` with no weight axis exposed by these accessors, so a variable font
   will appear as **one** family entry with `weight: 400` — which is correct for CSS (the `@font-face`
   / `font-weight` machinery handles the axis), but means you cannot enumerate the axis without
   reading `fvar`. Do not try to expand variable fonts into synthetic family rows.
8. **`.dfont`** is in DSH's extension set for macOS; irrelevant on Windows but harmless to keep in the
   filter if you want parity.

### 5.6 Two extra traps found

- **`libreoffice-kit` curates Office-private fonts separately** and dedupes by alias
  (`font-snapshot-worker.js:190-229`, `:395-405`, `:255-271`): it scans
  `%ProgramFiles%\Microsoft Office\root\vfs\Fonts\private` and
  `%LOCALAPPDATA%\Microsoft\FontCache`, then keeps a supplemental face only if it matches the curated
  `FAMILIES` set (Aptos, Calibri, Cambria, DengXian, Kaiti, Microsoft YaHei, Segoe UI, SimSun, …)
  **and** its aliases don't collide with the primary scan. Rationale: those files are not installed
  fonts and are partly unusable. **A user-facing picker should NOT include them by default** — a user
  who picks `Aptos` because LibreOffice can see it, but Chrome cannot, gets a broken UI font.
- **`%WINDIR%\Fonts` contains non-font files.** `C:\Windows\Fonts` has 574 files of which 377 match
  the font extensions — e.g. `desktop.ini`. Always filter by extension (and skip dotfiles), never
  enumerate blindly.

## 6. Recommended architecture

**Deliver the catalog over a variant-(c) HTTP route.** Justification, each point evidenced above:

1. **No core patch.** §1.8 — a new Remote namespace needs a fork of
   `dsh-api-remotes/lib/client.js` (hard-coded 23-value array). A `/api/fonts.catalog` route needs
   nothing outside the plugin.
2. **Proven in-tree, both halves, by two independent packages.** `dsh-client-ui-deliverables`
   (`ctx.connection.fetch.register` + `fetch`) and `dsh-client-hmr` (SSE) each ship host and client
   in one package with the identical split.
3. **Zero auth code in the client.** The route sits inside Connection's fence; I verified the 401
   live. Same-origin `fetch()` carries the cookie.
4. **Correct names.** fontkit on the host gives real `name`-table families; §5.1 quantifies why the
   registry cannot.
5. **fontkit is already bundled and loadable** from `app.asar.unpacked` (verified), and
   `libreoffice-kit/lib/font-snapshot-worker.js` is a 454-line working reference to copy from.

**Shape:**

- **Host** (`lib/index.js`): `inject: ["connection"]`; register `GET /api/fonts.catalog`; enumerate
  `[%SystemRoot%\Fonts, %LOCALAPPDATA%\Microsoft\Windows\Fonts]` filtered to
  `.ttf/.otf/.ttc/.otc`; parse each with `fontkit` (branching on `parsed.fonts`, skipping
  parse failures); **group by `cssFamily`**; attach `weight`/`italic`/`fixed` from
  `OS/2.usWeightClass` / `italicAngle` / `post.off.isFixedPitch`; attach localized name-table records
  as search aliases only; cache keyed on `dev/ino/size/mtimeMs/ctimeMs` + a `fontkit`
  version stamp (copy `font-snapshot-worker.js:275-292`); return
  `{ families: [{ cssFamily, aliases, faces: [...] }] }`. Guard with `maxFontFiles` /
  `maxFontFileBytes`, and run it once at `apply()` (optionally in a worker thread) rather than per
  request.
- **Client** (`lib/client.js`): `dsh.client.platform = "web"`; on picker open,
  `fetch('api/fonts.catalog')`; offer `cssFamily` as the value, localized `aliases` in the search
  box; on selection, set `--dsw-font-family` (UI) or `--ds-font-family-code` (code) on `:root` —
  the two variables the app already consumes (`dsh-client-ui-primitives/lib/markdown/CodeBlock.module.css:9,47`,
  `JsonTree.module.css:15`, `WebBlock.module.css:112`).
- **Verification before shipping:** render a probe string in each candidate family and compare
  `document.fonts.check()` / measured advance width against the fallback, then drop or flag any
  family that fails. This is the only way to catch the residual cases where a real name-table family
  is still not CSS-resolvable.
